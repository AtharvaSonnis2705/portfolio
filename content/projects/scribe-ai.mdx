## Problem

Meetings and voice notes hold decisions and to-dos, but nobody re-listens to a 40-minute recording to find them. Generic "summarize this" prompts also tend to invent owners and deadlines that were never said — which is worse than no summary.

## Approach & key decisions

**Two steps, two routes.** Transcription and summarization are separate API routes (`/api/transcribe`, `/api/summarize`). The user sees the transcript first, which makes the summary auditable and lets a failed summary be retried without re-uploading audio.

**Server-side keys only.** The browser never talks to OpenAI directly; it posts the file to a Next.js route handler that holds the key.

**Grounded output by instruction.** The system prompt tells the model to extract only what is present in the transcript, and the user prompt asks for a fixed structure:

```ts
// app/api/summarize/route.ts (simplified)
const response = await openai.responses.create({
  model: "gpt-5-mini",
  input: [
    {
      role: "system",
      content:
        "You are an expert meeting and conversation summarizer. Extract accurate, useful information from transcripts. Never invent information that is not present in the transcript.",
    },
    { role: "user", content: buildPrompt(transcript) }, // overview · key points · decisions · action items
  ],
});
```

Action items name a person or deadline **only when explicitly mentioned** — a small rule that removes the most damaging class of hallucination for this use case.

**Validate before spending tokens.** Uploads are checked for presence and a 25 MB size cap before any model call.

## Challenges & how I solved them

- **Hallucinated owners and dates.** Solved at the prompt level by constraining attribution to explicit mentions, and by showing the transcript alongside the summary so the user can verify.
- **Large files and failed requests.** Size validation up front and clear error messages from each route, so the UI can tell "bad file" apart from "model error".

## What I'd do next

- Stream the summary so long recordings feel responsive.
- Return structured JSON (schema-validated) instead of free text, so action items can be exported to a task tracker.
- Speaker diarization, so action items can be tied to who actually said them.
