## Problem

Booking a doctor usually means phone calls, double-booked slots and no record of payment. Clinics also need different views of the same data: patients want to find and book a doctor, doctors want their schedule, and admins need to manage both.

## Approach & key decisions

**Three apps, one API.** The repository is split into `frontend` (patients), `admin` (admins and doctors) and `backend`. Each UI only ships the screens its users need, while the Express API stays the single source of truth.

**Role-based access from the token up.** Passwords are hashed with bcrypt and sessions use JWTs, with separate authentication for users, doctors and admins — so protected endpoints are enforced by the API, not just hidden in the UI.

**MongoDB + Mongoose for flexible profiles.** Doctor profiles (specialty, fees, availability) and appointments map naturally to documents; Mongoose schemas add validation at the data layer.

**Cloudinary for media.** Media uploads go to Cloudinary rather than the API server's disk, keeping the backend stateless and easy to host.
